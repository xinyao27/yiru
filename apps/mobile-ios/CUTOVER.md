# Native iOS cutover

`apps/mobile` is the rollback implementation until every gate in
`cutover-readiness.json` is verified. Source coverage is necessary but is not release parity:
`migration-parity.json` records that each Expo route and runtime capability has a native owner, not
that every behavior has passed on a live Desktop runtime or a signed physical-device build.

`legacyRemovalAllowed` must remain `false` while any gate is pending. Deleting `apps/mobile` before
every gate is verified and the flag is explicitly enabled used to be rejected by a workspace
contract (`check-mobile-ios-cutover-readiness.mjs`); that script has since been deleted along with
the rest of the repository-contract scripts, so this is now a human-enforced rule with no machine
gate behind it.

## Gate snapshot as of 2026-08-17 (no longer machine-reproducible)

`vp run yiru-mobile-ios#verify:cutover` reported **8/14 gates verified, 6 pending; legacy retained**
on 2026-08-17. That command's underlying script has since been deleted, so this figure can no longer
be regenerated by running anything — it is a historical snapshot, not a live status. The source
ledger was complete at that point (29/29 routes and 126/126 runtime capabilities recorded Native
owners in `migration-parity.json`), but that ledger never replaced live state/mutation coverage,
signed-device evidence, or the
Apple/GitHub release steps below.
